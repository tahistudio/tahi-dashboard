# Requests Alignment Pass: Technical Audit

**Tree audited:** `main` at `d1a9736` (a descendant of `055c4ba`; working tree clean apart from untracked `docs/superpowers/`).
**Method:** five read-only lenses (wiring, api, state, ai, a11y) over the new Requests surface, its API routes, and the worker MCP server. No browser, no dev server, no Playwright. `npm run type-check` passes with zero errors; `npx vitest run` over the Requests unit specs passes 228 tests.
**Scope:** the new paths only. Legacy branches behind `railOn` / `newUi` / `NEW_DIALOG_FOR_EVERYONE` were read only where they share a handler with the new path or where the defect survives the gate flip.

---

## Summary for the founder

The alignment pass landed the shape it set out to land. The rail, the sliding view switcher, expanded sub-request rows, the board with its quick-add and On hold column, the delivery spine, the capacity strip, the rebuilt dialog and the detail rail all render, all wire to real endpoints, and the primary studio loops work: create a request, move it on the board, edit it inline, thread a message, nest and un-nest, bulk assign, approve as a client. Type-check is clean, the unit suite is green, the em dash sweep over the new component files is clean, and every design token the new code references is defined in `@theme`. Two pieces are genuinely well built: the `SegmentedControl` primitive (roving tabindex, arrow keys, reduced motion, focus ring correctly kept off the moving pill) and the board's ARIA scrollbar. The four design audits did their job on the visual layer.

What does not work sits underneath. Two flows are broken outright. `PATCH /api/admin/requests/bulk` applies status changes and archives to any request id with no team access check and no status whitelist, a tenancy hole reachable from the shipped bulk bar and from curl. The AI request wizard posts the client org under the wrong key, so every admin "Create request" from the AI panel returns 400 and nothing is ever written, in both of its mount points. Around those two, one consistent pattern: the writes that shipped in this pass skipped guard rails their older siblings already have. Five admin request routes (create, messages, steps, time entries, files) never call `requireAccessToOrg` while `[id]`, `nest`, `duplicate`, `participants`, `scope-flag` and `bulk-assign` all do. Two admin write paths store rich text unsanitised and the detail page renders it raw, so the render-side allowlist added in `055c4ba` is exported and imported nowhere. The Brand select in the new dialog writes nothing, which for any client using brand-scoped contacts means their request never appears in their portal at all. Before the gate flip, fix the bulk route's scoping and validation, the wizard's `clientOrgId` key, the five unscoped routes, the two unsanitised writers plus the raw render, the brand field (wire it or delete the control), and the request-number sequence so admin-created work stops disclosing the studio's cross-client volume to clients. Everything after that is polish that can ship behind the flip.

## Refuted claims

Recorded so nobody re-reports them.

- **List inline status chip PUTs a PATCH-only route (405, silent revert).** Real at `055c4ba`, already fixed at HEAD by `d1a9736`; `request-list.tsx:713` now sends `PATCH` and a grep for `PUT` in the file returns nothing.
- **Admin PATCH accepts any string for status and priority.** `app/api/admin/requests/[id]/route.ts:15-16` define `PATCHABLE_STATUSES` and `PATCHABLE_PRIORITIES` and lines 230-239 return 400 outside them. `draft` is intentionally allowed and is a first-class rail filter. Category remains unvalidated, but so does the POST, and there is no `REQUEST_CATEGORIES` vocabulary in the repo to validate against.
- **`runBulkAssign` reports every id as assigned regardless of what the route did.** The code fact holds but the wrong outcome is unreachable: `notFound` needs a hard-deleted request and nothing hard-deletes requests; `invalid` needs a contact or a missing field and the caller hardcodes `team_member` with a fixed role list; the only reachable divergence is `skipped`, where the end state matches the toast.
- **Custom kanban columns accept a free-text `statusValue` the create route then rejects.** The quick-add composer is suppressed on any non-creatable column (`request-list.tsx:1568` into `kanban-board.tsx:485-494`), and the drag path is guarded by `PATCHABLE_STATUSES` with a revert on 400, so a request can never acquire a custom status. The settings UI never sends `statusValue` on create or PATCH.
- **Activity filter preference bypasses the `useUserPreference` namespace.** The hydration effect is declared before the auto-open effect so it runs first and both `setState`s batch into one render; the claimed one-frame flash does not exist. The shared key is deliberate and asserted at `e2e/requests-detail.spec.ts:133`; renaming it would break that test and discard every stored value.
- **Admin AI create marks the request internal, hiding it from the client.** Prevented upstream: the same body sends the org under `orgId`, so the route 400s before the INSERT and `is_internal=1` is never written. Fold the flag into the B2 fix rather than treating it as a live defect.
- **`NewRequestDialog`'s `aiDraft` prop is never passed and the legacy copy skips the HTML conversion.** The prop is genuinely unwired, but both seeding effects are guarded by `if (!open || !aiDraft) return`, so neither body ever executes. Dead code in a branch already slated for deletion.
- **No test covers any AI path on the Requests surface.** `e2e/requests-dialog.spec.ts:157` drives the AI view swap and hand-back, and `components/tahi/__tests__/new-request-dialog.test.ts` imports and exercises `aiWizardProgress`, `openerForCategory` and `AI_MIN_STEPS`. The narrower residual (no test drives a stubbed draft back into the form fields, none asserts the outbound create POST body) is folded into B2's fix.
- **`aria-controls` on the new disclosures points at ids that only exist while expanded.** `aria-expanded` is bound to the same state that gates the render, so the IDREF is absent if and only if the control reports collapsed. axe-core explicitly exempts this case (`aria-valid-attr-value` skips IDREF validation when `aria-expanded === 'false'`), and no screen reader announces a broken reference. The proposed fix would also regress performance, since the body is deliberately unmounted to avoid walking every message's Tiptap HTML.
