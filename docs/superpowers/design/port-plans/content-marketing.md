## 0. How the prototype maps onto the app

The prototype borrows the Invoices family (`window.InvKit`, the `.inv` and `.cs` stylesheets) and the head-band rail (`window.TahiRail`). None of that CSS is ported. Existing primitives win wherever they differ:

| Prototype piece | App primitive to use |
|---|---|
| Head, `inv-head` | `PageHeader` (`components/tahi/page-header.tsx`) |
| Band, BandCell, BandSkeleton | `KPIStrip`, `KPICell` (`components/tahi/kpi-strip.tsx`), `SkeletonKPIStrip` (`skeletons.tsx`). A band meter becomes a small `ProgressBar` (`progress-bar.tsx`) inside the cell's `sub`. |
| Rail, RailSec, RailItem, RailLayout, RailCount, RailGrow | `RailLayout` (`components/tahi/rail/rail-layout.tsx`) with `RailViewItem`, `RailGroupLabel`, `RailSelect` (`rail-controls.tsx`). Reference consumer: `components/tahi/notifications/notifications-rail.tsx` and `notifications-content.tsx` (views in the rail, no sort, one trailing action). Below lg the rail folds into the Filters sheet on its own. |
| Tbl, Tr, Td | `DataTable` (`data-table.tsx`), including `mobileCard` below md and `expandable` plus `renderExpanded` for expand in place |
| Card, Facts | `Card` (`card.tsx`) with a header row: a 1.75rem icon tile on `--radius-leaf-sm`, title, meta line, right slot. Facts is a small local grid of label, value, line; never a second band. |
| Note | `Callout` (`callout.tsx`), tones info, warning, danger, tip |
| Empty | `EmptyState` (`empty-state.tsx`) with an explicit lucide icon on every call |
| Failed | `DataState` (`data-state.tsx`) error branch with Retry, or an `EmptyState` with an alert icon and a Try again action |

## 7. Risks

- `content-studio-content.tsx` is 175 KB and 4,672 lines with every pipeline action in it. Slice 1 must split it in a behaviour-free first commit and re-check each action (scan, ideation, seed, approve, round table start, discard, retry, publish, link apply and reject) before reskinning. A regression here stops the blog engine.
- Money and cost honesty: every AI figure is `estimatedUsdCents`, and the Opus rate card is known to be about 3x high (it trips the US$10 draft cap early). Any copy that says "real spend" is a lie; the briefs say "estimated".
- Paid actions during QA: ideation, round tables, audits, the Boardroom and sitemap reviewers all cost real money. Smoke must stay on read paths unless Liam asks.
- Client-visible writes during QA: publishing an announcement puts a banner on real client portals, and reviews statuses and pipeline data are real. Use drafts, the dummy client and delete test rows.
- Email: the Send by email switch reaches only allowlisted addresses while the delivery gate is closed. Do not change the gate. The announcement fan out has never been smoke-tested live (W-QA), so the accepted count in the toast is the first real read of it.
- The content engine ops residue (migrations 0060 to 0063 unverified on prod, PI-S1, S2, S5, S6.5 live QA owed) means some tabs may show thin or odd data that is a data problem, not a port bug.
- Two tab strips will now share one behaviour (client detail and content studio) through a copied pattern. A later lift into `components/tahi` is worth doing once both are stable; not in this port.
- MCP parity: the worker MCP has create, update, delete and send for announcements but no list tool, and nothing here adds a capability. The gap predates this port; adding `list_announcements` means touching `workers/mcp-server/src/index.ts`, which every module touches, so schedule it separately.
- `DataTable` expandable rows plus `mobileCard` on Reviews is a combination few pages use; check the expanded panel at 375.
- The design fixtures are sample data (Giant Group, a US$121 month, 201 URLs). Builders must read every figure from the API and never copy a fixture number into copy.
